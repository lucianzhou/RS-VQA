# v0.2.1 Stitch Apple-style UI redesign brief (draft)

Status: V0.5 strict-reference Stitch design set generated and ready for user
review; application code is unchanged.

Date: 2026-07-22

## Decision update

- Figma is no longer part of the UI workflow. No paid Figma plan, Figma export,
  or Figma maintenance is required.
- Stitch is the only UI design workspace for this phase.
- The previous dark-sidebar/light-workspace direction is rejected because it
  visually splits the product into two unrelated surfaces.
- New concepts must use a coherent whole-product theme: either all light or all
  dark. The all-light Apple-inspired direction is the primary proposal; an
  all-dark Codex/Apple-inspired direction is only a comparison proposal.
- Frontend implementation remains paused until the user reviews and freezes a
  Stitch direction.

## Primary visual direction: all-light

The target feeling is calm, expansive, precise, premium, and trustworthy. It
should learn from Apple product pages and system applications without copying
their branding.

- Background: `#F5F5F7`.
- Elevated surfaces: translucent white, approximately
  `rgba(255, 255, 255, 0.78)`, with restrained blur.
- Primary text: `#1D1D1F`.
- Secondary text: `#6E6E73`.
- Primary action is under review. The generic Apple blue `#0071E3` is no
  longer the recommended product identity; the current candidate is the
  Mineral Forest green `#245B49`.
- Typeface stack: `SF Pro Display`, `SF Pro Text`, `system-ui`,
  `PingFang SC`, sans-serif.
- Use generous negative space, thin separators, precise alignment, and soft
  hierarchy. Avoid dense card grids and heavy borders.
- Use simple monochrome system-style icons. Capsules are reserved for compact
  status or controls rather than applied to every component.

The following visual patterns are explicitly rejected:

- a dark navigation rail beside a light workspace;
- generic enterprise dashboard styling;
- neon, decorative gradients, map wallpaper, and excessive shadows;
- large collections of unrelated metric cards;
- looping decorative animation.

## Product layout

The desktop reference canvas is approximately `1440 x 960`.

### Left navigation

The navigation rail is approximately 276 pixels wide and uses the same light
material as the main workspace, separated by a hairline rather than a color
block. It contains:

- RS-VQA product identity and `新建分析`;
- expandable project folders, such as `城市土地利用` and `水域与植被`;
- image-based conversations within projects;
- ungrouped `最近对话`;
- `批量 VQA · 规划中`;
- `历史记录`;
- `分析报告 · 规划中`;
- `模型与设置` and a compact profile area;
- a sidebar-collapse control.

### Conversation workspace

One remote-sensing image creates one conversation. The active example is
`城市住宅区影像分析` and demonstrates several questions about the same image.

The workspace contains:

- conversation title, saved state, and model selector in the top bar;
- an integrated image-context block with thumbnail, filename, dimensions,
  `查看大图`, and `更换影像`;
- multi-turn user questions and concise model answers;
- a fixed multiline composer with free question input;
- a restrained capability-boundary note;
- model provenance presented below the answer instead of dominating it.

The primary path must remain visually obvious:

`上传影像 -> 自由输入问题 -> 获得简洁回答 -> 围绕同一影像继续提问`

## Model-source representation

The available model is shown as:

- `RS-VQA 研究模型`;
- deployment protocol `qdrop15 · predicted-soft`;
- model release ID, confidence, and `查看模型信息` disclosure in the answer
  provenance area.

The research output must remain a grouped-answer closed-set classification
result. The interface must not imply open-ended remote-sensing reasoning,
object detection, map analysis, or a general visual assistant.

A future `外部通用视觉模型` option may be visible for product completeness,
but it must be disabled and labelled `未配置`. Research-model and external-
model answers must never share an ambiguous source label.

## Planned functions shown in the design

The UI design should cover the intended product breadth even when the first
implementation does not activate every control. Unimplemented entries must be
visibly disabled or labelled `规划中` / `未配置`; they must not pretend to work.

Design coverage includes:

- welcome and image-upload state;
- image uploaded but not yet questioned;
- active multi-turn VQA conversation;
- inference in progress;
- low confidence and out-of-scope response;
- project folders and ungrouped conversation history;
- model selector and model information;
- batch VQA entry marked as planned;
- history;
- report/export entry marked as planned;
- settings;
- mobile core layout.

## Motion principles

Motion should help users understand continuity and state rather than decorate
the page.

- Default transitions are critically damped and have no bounce.
- Typical duration is 180-400 milliseconds.
- Sidebar collapse, image-preview expansion, upload completion, answer reveal,
  and model-selector popovers preserve spatial origin and continuity.
- Press feedback is immediate and animations can be interrupted.
- `prefers-reduced-motion` replaces spatial motion with short cross-fades.

### Geological green color study

Two all-light green variants were generated after the blue accent was judged
too generic and too strongly associated with Apple branding:

1. `RS-VQA Light Workspace - Mineral Forest`
   - primary `#245B49`;
   - pressed `#194536`;
   - supporting green `#4F7A67`;
   - pale selection `#E3EEE7`;
   - page background `#F3F5F1`;
   - primary text `#1D2420`;
   - secondary text `#68736D`;
   - muted ochre `#A87536` reserved for warning and low-confidence states.
2. `RS-VQA Light Workspace - Geological Sage`
   - primary `#557563`;
   - pressed `#3D5D4B`;
   - supporting lichen `#78927F`;
   - pale selection `#DCE8DE`;
   - page background `#F6F7F2`;
   - sidebar material `#EEF2EB`;
   - muted clay `#A96F4B` reserved for warning and low confidence.

The current recommendation is `Mineral Forest`. It provides stronger product
recognition and clearer action/state contrast while keeping the sidebar and
workspace in one continuous light system. `Geological Sage` is softer and more
atmospheric, but Stitch changed the image hierarchy in that generated screen,
so its layout must not replace the approved workspace structure.

The preferred implementation direction is therefore:

`Apple-inspired interaction and material discipline + Mineral Forest identity`

This keeps the interface quality references without making the product look
like an Apple-branded application.

### V0.5 strict-reference review set

The first six-screen `V0.3` board is retained only as a rejected exploration.
Although its palette was green, it changed the application shell between
screens, introduced unrelated top navigation, and sometimes removed the
project/conversation sidebar. `V0.4-01` improved structural fidelity but used
the pale green background too broadly, which made the interface feel like a
theme skin instead of an Apple-inspired light workspace.

V0.5 therefore freezes the following measurable surface hierarchy:

- at least 80% of each desktop screen reads as white or neutral;
- the main workspace, conversation canvas, cards, and upload surface are white;
- `#F3F5F1` is limited to the pale sidebar and secondary support surfaces;
- `#E3EEE7` is limited to selected rows and quiet semantic highlights;
- `#245B49` is limited to primary actions, focus, and small identity details;
- large green backgrounds, green overlays, blue accents, gradients, dashboard
  metric grids, and newly invented product navigation are prohibited;
- every state is generated independently from a calibrated reference to reduce
  cross-screen layout and palette drift.

### Current design recommendation

Use the all-light Mineral Forest concept as the implementation candidate. It best preserves
the core image-question-answer path, gives the research-model provenance a
secondary but discoverable hierarchy, and avoids the visual split of the old
dark-sidebar prototype.

The dark concept should remain an optional future theme rather than the first
implementation target. Before implementation, the light concept still needs
user review for exact density, typography, image metadata, and inactive
planned-feature wording.

## Review gate

Frontend development may start only after the user reviews the generated
Stitch concepts and confirms:

1. all-light or all-dark theme;
2. navigation density and hierarchy;
3. image-context presentation;
4. message and provenance hierarchy;
5. model-selector wording and disabled future-model state;
6. which planned controls should appear inactive in the first implementation.
