# RS-VQA v0.11.0 技术方案与功能介绍：可信 Provider 准入与恢复

> 日期：2026-07-30
>
> 分支：`feature/trusted-application-p1`
>
> 研究模型发布未修改。

## 1. 目标

Gemini、Qwen3-VL 和 RS-Bot 的远程模型调用此前已有超时与短重试，但缺少用户级频率、并发、
token 预算和可恢复熔断。`estimated_cost_usd` 字段存在，但没有受版本控制的价格来源。

本版本增加统一 Provider 可靠性层。研究 ViLT、批量研究模型 worker 和模型发布物不经过该层，
中转站故障不会改变研究模型可用性或结果。

## 2. 准入控制

Redis Lua 脚本在一次原子操作中完成：

- 按用户、Provider、`VISION`/`AGENT` 工作负载计数；
- 分钟请求上限；
- 带过期时间的并发租约；
- 单次输入项上限；
- UTC 日 token 预算预留。

调用结束后释放并发租约，并以真实 token usage 调整预留量；上游没有返回 usage 时保留预留量，
避免把未知消耗当作 0。Redis 不可用时外部调用失败关闭，不向外发送图像或 Agent 请求。

默认策略：

| 工作负载 | 每分钟 | 每用户并发 | 单次输入 | 日 token | 单次预留 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 视觉 | 12 | 2 | 1 | 100000 | 8192 |
| RS-Bot | 20 | 1 | 1 | 200000 | 40000 |

## 3. 熔断与恢复

- 仅 408、429、5xx、连接中断、读取超时等瞬时故障计入熔断；
- 401、403、404、输入校验和准入拒绝不计入熔断；
- 连续 3 次瞬时失败后打开 30 秒；
- 到期后只允许一个半开探测；
- 探测成功恢复，失败重新打开；
- Provider 列表在熔断期间显示 `UNAVAILABLE`，并附带不含端点信息的 circuit 状态。

Gemini 与 Qwen 的用户错误均使用受控中文消息。第三方响应体、Base URL 和 API Key 不进入
API、Provider 描述或版本文档。

## 4. 价格与成本

价格目录使用显式 `pricingVersion + provider/model + input/output USD per million tokens`。
只有价格和 token usage 同时完整时才计算 8 位小数成本；否则：

```text
pricingState=UNKNOWN
estimatedCost=unknown
estimated_cost_usd=NULL
```

默认配置不假定中转站价格。管理员核验新价格后必须修改版本号，避免历史调用被新价格静默重算。

## 5. 验证

- Gateway 全量：137 tests，0 failure/error，8 个可选外部环境测试按条件跳过；
- 本地 MockWebServer：覆盖 400、401、403、404、408、429、503、读取超时、空响应和格式错误；
- 熔断单元测试：连续失败、短路、30 秒后半开探测、成功恢复；
- Redis 真实集成：并发租约、分钟限流、日预算预留与调用后调整全部通过；
- `git diff --check` 通过；
- 测试未访问真实中转站，也未读取真实 API Key。

## 6. 边界

- 本版本没有运行 50 条付费 Gemini 评测；
- 外部批量视觉任务尚未开放，单次视觉输入固定为 1；
- 熔断状态保存在单 Gateway 进程；准入和预算由 Redis 跨请求协调；
- 中转站数据处理条款与价格真实性仍需运营者单独核验。
