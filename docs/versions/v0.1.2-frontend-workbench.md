# RS-VQA v0.1.2：遥感图像对话工作台

> 状态：已完成
>
> 版本：v0.1.2
>
> 日期：2026-07-20
>
> 论文主线：跨模态特征融合机制及微调策略研究与应用

## 1. 本版目标

将 v0.1.0 的表单式页面重构为面向 VQA 主路径的遥感图像对话工作台。目标不是叠加装饰，而是让用户一眼看清三件事：

1. 当前哪一张影像正在被分析；
2. 应该在哪里提问；
3. 回答来自研究模型、Mock 还是不可回答边界。

本版修复了原首页 Hero 标题因超大字号与可用宽度不匹配而断裂的排版问题，并以更接近对话式 AI 工具的结构替代原有双卡片表单布局。

## 2. 用户可见功能

| 区域 | v0.1.2 行为 |
| --- | --- |
| 左侧影像上下文 | 显示上传入口、预览、文件名、就绪状态与模型能力范围 |
| 右侧对话工作台 | 显示空状态、当前输入、结果卡与固定在底部的提问器 |
| 提问器 | 保留自由中英文问题输入、示例问题、附件/换图入口和禁用状态 |
| 结果卡 | 将 `answered`、`unsupported`、`model_unavailable` 与 Mock 来源以明显样式区分 |
| 响应式布局 | 大屏双栏；窄屏自动变为影像上下文在上、对话区在下的单栏 |
| 可访问性 | 使用原生上传按钮、可见键盘焦点、表单标签、错误提示和 reduced-motion 支持 |

## 3. 设计方案

### 3.1 设计定位

具体对象是“研究演示中的遥感图像分析者”，页面唯一核心任务是：把一张图带入对话并提出一个受支持的问题。

因此采用“影像上下文 + 对话画布 + 底部 composer”结构，而不是营销首页或数据大屏。对话区的留白用于承接结果卡和未来多轮记录；左侧始终保留输入影像，使用户不必在对话中丢失图像上下文。

### 3.2 视觉令牌

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 深海墨 | `#173440` | 影像上下文栏与专业感基调 |
| 雾白 | `#F8FBFB` | 对话画布和阅读空间 |
| 地形绿 | `#C6E5D2` | 品牌标识、就绪状态与正向提示 |
| 测绘青 | `#488595` | 结构标签与交互强调 |
| 暖沙黄 | `#FFF8E7` | Mock 模式的显式风险提示 |

标志性元素是影像上传框与左侧栏中的低对比坐标网格：它表达“空间影像输入”，不伪装成模型热力图、检测框或研究结论。

### 3.3 结构与接口边界

本版仅修改 `apps/web`：Vue 状态、`POST /api/v1/vqa/answers` 请求字段和 FastAPI/Spring 后端均未改变。

```text
影像上下文栏 ── 选择/拖入图片 ─┐
                                 ├─ POST /api/v1/vqa/answers ── 模型服务
对话提问器 ── 问题文本 ──────────┘
                                      ↓
                         结果卡 + 来源/能力边界提示
```

## 4. 研究与产品边界

- 视觉重构不改变任务定义：仍是 RSVQA-HR grouped-answer closed-set classifier 的应用界面。
- `mock_demo` 的回答仍在结果卡中以黄色提示明确标出，不能被理解为论文模型输出。
- 对不支持的问题仍展示能力限制，不把通用文本生成冒充为 VQA 回答。
- 预览框的坐标网格仅是视觉语言，不代表地理坐标、测绘精度、目标定位或模型注意力。

## 6. 已知限制与下一版门槛

- 当前没有账户、历史会话或真实多轮上下文；“新对话”只是单次页面会话的视觉表达。
- 对话区目前只渲染最近一次模型响应，未来引入历史前需先设计数据治理和审计边界。
- 真实 predicted-soft 运行时接入仍以研究仓库发布契约为前置条件；不得用该界面掩盖 Mock、oracle、routed 或外部 VLM 来源。
- 后续若增加 Agent/RAG/外部模型，需要在同一界面中维持严格的输出来源区分，并新增独立版本方案与验收记录。
