# v0.8.1 集成审查

- 日期：2026-07-26
- 状态：集成候选，尚未合入 `main`
- 分支：`integration/rs-bot-v0.8-reviewed`

## 目标

按以下顺序组合并审查四个独立交付：

1. 研究模型问题规范化与真实推理链修复。
2. Gemini OpenAI 兼容中转 Provider。
3. RS-Bot 规划循环、工具策略与运行溯源。
4. RS-Bot 工作区抽屉和独立会话界面。

该分支只用于集成验证；`main` 和原四个功能分支均保持不变。

## 本次修正

- RS-Bot 调用项目、会话或批任务工具时，资源 ID 由已认证的会话上下文强制写入，模型不能通过工具参数切换分析范围。
- 单轮模型响应使累计 token 超出预算后，立即停止，不再执行该响应中提出的工具。
- Agent SSE 与 Nginx 读取超时统一为 330 秒，高于最大 300 秒规划预算，避免原 60/65 秒超时提前中断用户连接。
- 中转站 HTTP 错误日志不再记录第三方响应正文，避免密钥或上游内部信息以编码、截断等形式绕过字符串脱敏。
- Python smoke 与 Java Provider 均发送稳定、可识别的 RS-VQA `User-Agent`；避免 Cloudflare 以 1010 拒绝 Python/Java 默认客户端特征。

## 集成门槛

- 数据库必须先执行 `V10__question_normalization_audit.sql`，再执行 `V11__rs_bot_run_provenance.sql`。
- 现有本机测试库已先应用 V11，不能直接启动本集成分支。测试数据可丢弃时应重建应用数据库卷；需要保留数据时必须制定并验证单独的 Flyway 修复方案。
- Gemini 文本、流式和工具调用必须通过真实中转站 smoke；结构化输出作为可选增强单独报告，视觉角色必须另行通过图像输入契约后才能启用。

## Gemini 中转实测

2026-07-26 使用 `gemini-3.6-flash` 和 OpenAI 兼容端点完成真实 smoke：

- 普通文本对话通过，观测延迟约 8.2 秒。
- SSE 流式传输通过，共收到 6 个数据块，观测延迟约 5.7 秒。
- 工具调用通过，模型正确提出 `project_summary` 调用。
- `response_format=json_object` 未返回可直接解析的 JSON。当前 RS-Bot 不依赖该能力；报告、写操作参数和审计均由 Java 确定性流程生成。
- 图像输入未测试，Gemini 视觉角色继续保持关闭。

因此，Gemini 已满足 RS-Bot 当前版本的文本与工具规划要求；不能据此宣称结构化输出或外部视觉能力可用。

## 失败审计事务

`TrustedAgentService` 不再用一个事务包住 LLM 网络调用和全部工具执行。运行创建、每次工具轨迹以及成功/失败收尾分别在短事务中提交。持久化测试模拟“工具已完成，随后规划模型连接中断”，并验证数据库仍保留失败运行与已完成工具轨迹。

## 集成环境验收

- 重建本机测试数据库后，Flyway 按 `V1` 至 `V11` 连续执行，`V10` 先于 `V11`。
- 正式研究模型运行时就绪，release ID 为 `rsvqa-hr-qdrop15-predicted-soft-20260724-8510bc9`。
- 真实 RS-Bot 请求由 `gemini-3.6-flash` 完成两步规划，调用 `current_model_release` 与 `model_capabilities`；运行、工具、token 和停止原因均已持久化。
- 中文与规范英文的 presence、count、area、comparison 四类输入完全同预测，且服务结果与直接 release runtime 结果一致。
- 一致性图像属于无 RSVQA-HR 标签的工程测试图，只证明调用路径一致，不证明预测正确率。

## 模型边界

研究模型仍为 frozen `qdrop15 + predicted-soft` RSVQA-HR 闭集分类器。规范化只改变送入模型的问题文本，不改变或规则修正模型原始答案。Gemini 和 RS-Bot 输出必须保持外部模型/Agent 来源标识，不得作为论文研究模型预测。
