# v0.8.1 集成审查

- 日期：2026-07-26
- 状态：集成候选，尚未合入 `main`
- 分支：`integration/rs-bot-v0.8-reviewed`

## 目标

按以下顺序组合并审查四个独立交付：

1. 研究模型问题规范化与真实推理链修复。
2. Gemini OpenAI 兼容中转 Provider。
3. RS-Bot 规划循环、工具策略与运行溯源。
4. RS-Bot 工作区抽屉和独立会话界面。

该分支只用于集成验证；`main` 和原四个功能分支均保持不变。

## 本次修正

- RS-Bot 调用项目、会话或批任务工具时，资源 ID 由已认证的会话上下文强制写入，模型不能通过工具参数切换分析范围。
- 单轮模型响应使累计 token 超出预算后，立即停止，不再执行该响应中提出的工具。
- Agent SSE 与 Nginx 读取超时统一为 330 秒，高于最大 300 秒规划预算，避免原 60/65 秒超时提前中断用户连接。
- 中转站 HTTP 错误日志不再记录第三方响应正文，避免密钥或上游内部信息以编码、截断等形式绕过字符串脱敏。

## 集成门槛

- 数据库必须先执行 `V10__question_normalization_audit.sql`，再执行 `V11__rs_bot_run_provenance.sql`。
- 现有本机测试库已先应用 V11，不能直接启动本集成分支。测试数据可丢弃时应重建应用数据库卷；需要保留数据时必须制定并验证单独的 Flyway 修复方案。
- Gemini 文本、流式、结构化输出和工具调用必须通过真实中转站 smoke；视觉角色必须另行通过图像输入契约后才能启用。

## 已知阻断项

`TrustedAgentService` 当前在一个长事务中完成 LLM 调用、工具调用和审计写入。运行中抛出未检查异常时，失败状态和工具轨迹可能随事务一起回滚；而已执行工具又只在完整规划结束后统一持久化。合入 `main` 前应把“运行创建、每次工具轨迹、成功/失败收尾”拆成短事务，并增加失败中途仍可查询审计记录的集成测试。

## 模型边界

研究模型仍为 frozen `qdrop15 + predicted-soft` RSVQA-HR 闭集分类器。规范化只改变送入模型的问题文本，不改变或规则修正模型原始答案。Gemini 和 RS-Bot 输出必须保持外部模型/Agent 来源标识，不得作为论文研究模型预测。
