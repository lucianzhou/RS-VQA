# RS-VQA v0.8.3: Provider-aware VQA Rendering

## 版本目标

修复工作区 VQA 请求期间始终显示 RS-VQA 头像的问题，并让 Gemini、Qwen3-VL 的生成式回答按安全 Markdown 展示。研究模型仍保持闭集纯文本结果，不改变推理协议或历史数据。

## 功能变更

- 发送问题时锁定本次请求的 Provider，不受请求期间下拉选择变化影响。
- 等待状态根据请求 Provider 显示对应头像和明确模型名：
  - `RS-VQA 研究模型`
  - `Gemini-3.6-flash`
  - `Qwen3-VL 32B`
- Gemini、Qwen3-VL 回答支持标题、段落、列表、强调、链接、代码块和分隔线。
- RS-Bot 与 VQA 生成式回答复用同一个安全 Markdown 组件和协议过滤规则。
- RS-VQA 闭集分类结果继续使用原始纯文本主答案样式，不经过 Markdown 解释。

## 安全边界

- 不使用 `dangerouslySetInnerHTML`。
- 禁止原始 HTML、Markdown 图片和危险链接协议。
- 历史回答使用各自持久化的 Provider 与模型信息，不跟随当前下拉选项变化。

## 验收标准

- 选择 Qwen3-VL 后发送问题，等待状态必须显示 Q 图标和 `Qwen3-VL 32B 正在分析当前影像…`。
- 选择 Gemini 后发送问题，等待状态必须显示 G 图标和 `Gemini-3.6-flash 正在分析当前影像…`。
- Gemini、Qwen3-VL 回答中的 Markdown 标记不得作为普通字符直接显示。
- RS-VQA 的闭集预测仍以原始答案文本为主，不被 Markdown 渲染器改写。
- 桌面和移动端均不得因长文本、代码或模型名产生横向滚动。

## 验证结果

- 前端单元测试：37 项通过。
- TypeScript 类型检查与生产构建通过。
- 工作区主 VQA Playwright 流程单独重跑通过。
- 实际页面确认 Qwen 请求显示 Q 图标和正确等待文案。
- 实际页面确认历史 Gemini Markdown 已渲染为段落、列表、强调等语义元素。
- E2E 的 Gemini 边界测试在 Provider 已配置时不再发送真实图像请求，避免消耗额度和污染演示数据。

完整工作区 E2E 中仍有两个与本版本无关的环境性缺项：BGE/Milvus 未启动时知识库引用用例无法完成；实时 Gemini RS-Bot 的自由工具规划不保证每次调用旧测试指定的固定工具。两者不影响本版本的 Provider 等待状态与 Markdown 展示验收。
