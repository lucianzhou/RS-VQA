# RS-VQA v0.6.0 技术方案与功能介绍：Gemini 中转站 Provider

> 状态：已完成（外部视觉能力的 live 验证等待用户配置密钥，见第 7 节）
> 日期：2026-07-26
> 分支：`feature/gemini-relay-provider`
> 论文：跨模态特征融合机制及微调策略研究与应用
> ADR：[`adr-005-gemini-relay-provider.md`](../architecture/adr-005-gemini-relay-provider.md)

## 1. 版本目标

把外部 Gemini 能力从 Google 官方 endpoint 迁移到可配置的 OpenAI 兼容中转站，并把
“文本/工具模型”与“视觉 VQA 模型”拆成两个必须各自验证的角色。

本版不做：不改研究模型任何行为、不用中转站结果替代或改写研究模型预测、
不在未验证前宣称任何中转站模型具备视觉能力。

## 2. 用户可见变化

| 变化 | 说明 |
| --- | --- |
| 外部视觉 Provider 默认 `UNCONFIGURED` | 未指定并验证 vision 模型前，UI 不显示外部通用视觉模型可用 |
| Provider 显示名 | `外部通用视觉模型（中转站）`，模型 ID 未配置时显示“未配置” |
| 失败提示更具体 | 区分“未启用/缺 base URL/缺密钥/未指定模型 ID”，并说明该设哪个环境变量 |

## 3. 配置

```
RSVQA_GEMINI_ENABLED=false            # 中转站总开关
RSVQA_GEMINI_BASE_URL=                # 例如 https://api.qlhazycoder.top
RSVQA_GEMINI_API_KEY=                 # 服务端专用，独立于旧的 GEMINI_API_KEY
RSVQA_GEMINI_COMPLETIONS_PATH=/v1/chat/completions

RSVQA_GEMINI_AGENT_ENABLED=false      # RS-Bot 文本/工具模型角色
RSVQA_GEMINI_AGENT_MODEL=gemini-3.6-flash
RSVQA_GEMINI_AGENT_TIMEOUT_SECONDS=90
RSVQA_GEMINI_AGENT_MAX_RETRIES=2

RSVQA_GEMINI_VISION_ENABLED=false     # 外部视觉 VQA 模型角色
RSVQA_GEMINI_VISION_MODEL=            # 无默认值：必须显式指定已验证模型
RSVQA_GEMINI_VISION_TIMEOUT_SECONDS=60
RSVQA_GEMINI_VISION_MAX_RETRIES=2
```

密钥与 base URL 只存在于服务端进程配置，不进入前端、descriptor、日志或错误消息。
`.env.example` 只有空值占位；真实值放在未跟踪的 `.env`。

## 5. 两个重要的实现修正

### 5.1 读超时不是 `ResourceAccessException`

契约测试实测发现：`SimpleClientHttpRequestFactory` + `RestClient` 的读超时会被包装成普通
`RestClientException`，只有 cause 链末端才是 `SocketTimeoutException`。按包装类型分类会导致：

- 重试模板不重试超时；
- provider 把超时错标成 “malformed response”。

修正：重试注册 `IOException` 并 `traversingCauses()`；provider 用
`OpenAiCompatibleEndpoint.transportFailure(...)` 按 cause 链判定。

### 5.2 429 不能触发 UNAVAILABLE 闩锁

首轮实现依赖框架默认错误分类，结果 429 被判为不可重试，还会把 provider 永久闩锁为
`UNAVAILABLE`——限流会被误判成“该模型不支持视觉”。修正为显式状态码映射：
408/429/5xx 可重试，其余 4xx 不重试且触发闩锁。

## 7. 待用户操作（阻塞项）

**`gemini-3.6-flash` 的视觉能力尚未验证。** 公开页面没有给它标注多模态，只有
`gemini-3.1-pro-preview` 明确标注多模态；页面还显示近期成功率约 62.5%。因此本版不作任何
视觉可用性声明。

请在本地安全配置后运行（脚本只读环境变量，不读 `.env`，报告不含密钥与主机名）：

```bash
export RSVQA_GEMINI_BASE_URL=https://<relay-host>
export RSVQA_GEMINI_API_KEY=<server-side-secret>
export RSVQA_GEMINI_AGENT_MODEL=gemini-3.6-flash
export RSVQA_GEMINI_VISION_MODEL=<待评估模型>
python scripts/gemini_relay_live_smoke.py
```

结果判定：

- `image_input` 通过 → 将该模型配置为 vision 角色，并在本文件记录验证日期与模型 ID；
- 不通过 → `gemini-3.6-flash` 仍可作为 RS-Bot 文本/工具模型；外部视觉保持 UNAVAILABLE；
  再评估该中转站中标注多模态的模型。

**不要把密钥粘贴到任何对话或文档中。**

## 8. 数据外发与研究边界

- 启用 vision 角色意味着用户上传的遥感图像会离开本系统发往第三方中转站；
  现有的 `externalImageOptIn` 用户级许可仍是硬前置条件。
- 中转站是第三方转发，不是模型厂商官方端点，链路多一跳；公开成功率约 62.5%，
  不应作为稳定依赖。
- 研究模型路径完全不经过中转站。外部模型输出标记为 `EXTERNAL_VLM` /
  `external_vlm_assist`，与 `research_vilt_predicted_soft` 严格分离，
  且不得用于改写或伪装研究模型原始预测。
- 研究模型指标不变：test OA/AA = 0.8401412 / 0.8390032，
  test_phili OA/AA = 0.8031558 / 0.7975786；不声称 SOTA。
