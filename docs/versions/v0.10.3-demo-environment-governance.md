# v0.10.3 答辩演示环境治理

> 日期：2026-07-30
>
> 分支：`fix/trusted-runtime-p0`
>
> 论文题目固定为《跨模态特征融合机制及微调策略研究与应用》

## 1. 目标

本版本为本地论文答辩提供可重复的 Demo seed/reset，同时防止“清理测试数据”误删真实用户、
模型发布、知识库或冻结答辩集。它只治理本地演示环境，不扩大为公网管理功能，也不改变研究模型。

## 2. 重置边界

入口为：

```text
POST /api/v1/demo-environment/reset
{"confirmation":"RESET_LOCAL_DEMO"}
```

执行必须同时满足：

- Demo 环境开关已启用；
- 请求已通过 Session Cookie 认证和 CSRF；
- 当前身份严格为数据库中 `demo=true` 的 `local-demo`；
- 确认短语精确等于 `RESET_LOCAL_DEMO`；
- 当前模型服务为 `real + predicted_soft` 且 release ID 与配置的不可变发布一致；
- 24 条 questions-only 清单 SHA-256 与冻结值一致。

只清理 `local-demo` 所属的项目、对话、上传副本、消息、模型调用、批任务、报告、
RS-Bot 会话/运行/工具调用/操作提案及审计记录。数据库删除在同一事务中执行。

以下内容永不由该操作删除：

- `app_user` 中的演示用户和所有真实用户；
- 任意用户的 `model_release`；
- `PUBLIC` 或 `PRIVATE` 知识文档及向量记录；
- 模型、checkpoint 和发布目录；
- `data/defense-benchmark-v1`；
- 其他用户的项目、会话、任务、报告和上传文件。

旧上传文件只在数据库事务提交后删除，且文件路径必须位于 `local-demo` UUID 命名空间。
事务回滚时会清理由本次初始化新建的上传副本，不会删除旧工作区。

## 3. 确定性演示内容

数据源：

```text
data/defense-benchmark-v1/showcase-24-questions.csv
SHA-256=4dc3608b2c5853b2c8f63822331af50d348037c005365a1d17743d783b6bc283
```

初始化生成：

- 1 个“答辩演示 · 受控遥感问答”项目；
- 3 个带图会话：单图 Presence、同图多轮、Count 人工复核；
- 1 个 24 项批量任务，Presence、Count、Area、Comparison 各 6 条；
- 2 个 RS-Bot 上下文，分别绑定答辩项目和批量任务。

批量项严格为“一张图像对应一个问题”，不调用会产生图像 × 问题笛卡尔积的通用批量创建接口。
冻结图像只读，初始化先把所需图像复制到普通上传空间。

单图、多轮与批量结果都通过现有 `VqaService`、模型服务和批量租约 worker 生成。系统不会直接
插入预测，不会伪造 Gemini/RS-Bot 回答，也不会根据展示子集修改 normalizer、prompt、阈值、
答案词表或 checkpoint。

24 项展示集按冻结规则覆盖不同答案组，包含成功行为和真实失败边界，但不保存或暴露逐样本 gold。
Count 输出继续提示非零和密集目标存在系统性低估风险。

## 4. 运行方式

Compose 将冻结答辩集只读挂载到 Gateway：

```text
./data/defense-benchmark-v1:/opt/rsvqa/defense-benchmark-v1:ro
```

显式执行：

```bash
./scripts/reset_demo_environment.sh
```

响应状态为 `INITIALIZING_RUNTIME_OUTPUTS`，表示数据库和上传副本已经建立，研究模型输出正在异步
生成。Real Runtime 较慢时应在批量任务页观察进度；Provider 故障不会被替换为伪造答案。

Production profile 固定关闭 Demo 登录和 Demo 环境重置。
Mock、未就绪、非 predicted-soft 或 release 不一致时，会在数据库清理前失败关闭。

## 5. 验证证据

自动测试覆盖：

- 匿名请求被拒绝；
- 已认证但缺少 CSRF 的请求被拒绝；
- 非 `local-demo` 身份被拒绝；
- 错误确认短语在读取清单或删除数据前失败；
- Mock Runtime 和 release ID 不匹配均在读取清单或删除数据前失败；
- 会话预填严格先于批任务 worker 启动，避免初始化时争抢模型运行时；
- questions-only 清单哈希及四类各 6 条约束；
- 文件删除不能跨越用户 UUID 命名空间；
- PostgreSQL 中连续重置两次后只保留一套演示数据；
- 24 个批量项保持一图一问；
- 真实用户项目、Demo 私有知识、公共知识、模型发布和冻结文件哈希保持不变；
- 旧演示上传副本在事务提交后删除。

测试期间使用独立临时 PostgreSQL，不会重置当前开发数据库中的 `local-demo` 数据。

验证命令与结果：

```text
Gateway：mvn -q test
PostgreSQL：RSVQA_DEMO_INTEGRATION=true
            mvn -q -Dtest=DemoEnvironmentPostgresIntegrationTest test
Compose：docker-compose --env-file /dev/null config --quiet
脚本：bash -n scripts/reset_demo_environment.sh
差异：git diff --check
```

Gateway 全量测试与显式启用的 PostgreSQL 测试合计覆盖 123 个测试方法，结果为
`failures=0`、`errors=0`；另外 5 个依赖可选外部环境的测试按既有条件跳过。全新 PostgreSQL
实例从空库成功应用 14 个 Flyway 迁移。

另使用独立端口、临时数据库和现有只读 Real Runtime 完成一次真实 HTTP 验收。脚本通过
Session、CSRF 和确认短语后返回 `INITIALIZING_RUNTIME_OUTPUTS`，最终临时环境稳定为：

- 1 个答辩项目；
- 3 个带图会话和 4 次真实会话推理；
- 1 个批任务，24/24 个条目进入 `COMPLETED`；
- 2 个 RS-Bot 上下文；
- `DEMO_ENVIRONMENT_RESET` 与 `DEMO_CONVERSATION_SEED` 均记录为 `SUCCESS`。

验收没有读取逐样本答案，也没有操作当前开发数据库；临时 Gateway、数据库、端口转发和上传副本
在验证后均已删除。

当前 P0 分支重新构建 Gateway、Web 和 Knowledge Service，并保留既有 Real Runtime 后，又完成
一次 Playwright 串行、零重试全链路验收：桌面、笔记本、平板和手机共 16/16 项通过。验收覆盖
单图多轮问答、受控 Agent 操作、BGE/Milvus 检索、批任务及缩略图、确定性报告、Gemini
失败关闭、RS-Bot 上下文和响应式布局。直接写接口的测试请求与真实 React 客户端一致，从
`XSRF-TOKEN` Cookie 读取原始令牌并通过服务端声明的 Header 回传；服务端 CSRF 保护未放宽。

## 6. 已知限制

- 重置是本地答辩运维动作，不是普通用户的数据删除功能。
- 初始化后的模型推理是异步的；接口成功不代表 24 项已经全部完成。
- 如果真实研究模型服务不可用，条目会按正常批任务语义失败或等待恢复，不会降级成 Mock。
- 本版本没有依据 24 条展示子集报告总体准确率，也没有读取或提交逐样本答案、预测或受限 gold。
- 本版本不实现 P1 Provider 限流、RS-Bot 任务集、前端动效升级或多用户生产运维。
