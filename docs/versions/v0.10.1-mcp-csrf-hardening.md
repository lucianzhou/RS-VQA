# v0.10.1 MCP 与 CSRF 加固

状态：已实现并通过本地单元、集成与真实进程验证

日期：2026-07-30

## 目标

关闭默认公开的 MCP Server，恢复基于 Session Cookie 的浏览器写请求 CSRF 防护，并收敛
生产环境中的 Demo 登录、Swagger、Actuator 与会话 Cookie 暴露面。本阶段不改变 RS-Bot
工具集合、研究模型、RAG 内容或业务功能。

## MCP 安全契约

- MCP Server 默认关闭，`RSVQA_MCP_ENABLED` 的默认值为 `false`。
- MCP 使用独立的无状态 Spring Security filter chain，不读取浏览器 Session，也不使用
  CSRF Cookie。
- 启用 MCP 时必须同时设置至少 32 字符的 Bearer Token 和明确的内部 principal；缺少任一
  配置时 Gateway 启动失败。
- 匿名、错误 Token 和正确 Token 的请求都只写入一条 `MCP_REQUEST` 审计事件。
- MCP 工具仍为只读工具；生产入口 Nginx 对 `/mcp` 统一返回 404，仅允许 backend
  内部网络按需访问 Gateway。
- 日志和配置对象不会输出 Bearer Token。

MCP 的服务端配置只允许通过未跟踪的环境变量注入：

```text
RSVQA_MCP_ENABLED=true
RSVQA_MCP_BEARER_TOKEN=<at-least-32-characters>
RSVQA_MCP_PRINCIPAL=<existing-internal-user>
```

## 浏览器 CSRF 契约

- 所有 `/api/**` 写请求恢复 Spring Security CSRF 校验。
- `GET /api/v1/auth/csrf` 允许匿名调用，用于建立 CSRF Cookie 与 header 名称契约。
- React API 层在普通 fetch、SSE POST 和批量上传 XMLHttpRequest 中统一发送
  `X-XSRF-TOKEN`。
- Spring SPA CSRF 响应体中的 token 是掩码值，浏览器请求 header 必须使用
  `XSRF-TOKEN` Cookie 中的原始值；前端不使用响应 JSON token 作为回退。
- CSRF 获取请求被合并，403 或登出后清除缓存，下次写请求重新建立安全上下文。

## 会话与生产配置

- 手工登录和 Demo 登录在已有 Session 上认证时轮换 Session ID。
- 默认 profile 关闭 Demo 登录；`demo` profile 才显式开启。
- `production` profile 设置 Session Cookie 为 `Secure`、`HttpOnly`、
  `SameSite=Lax`。
- `production` profile 关闭 Swagger/OpenAPI，只公开 Actuator health。
- Nginx 仅转发 readiness/liveness；其他 Actuator、MCP、Swagger 和 OpenAPI 路径
  返回 404。
- 未认证 `/api` 返回 401；被配置关闭的端点保持 404，不再被通用异常处理转换成 500。

## 配置边界

Compose 新增以下空值或关闭状态的显式传递：

- `RSVQA_MCP_ENABLED=false`
- `RSVQA_MCP_BEARER_TOKEN=`
- `RSVQA_MCP_PRINCIPAL=`

真实 Token 只能放在未跟踪的环境文件或部署平台 Secret 中，不能写入 `.env.example`、
Compose 默认值、日志、版本文档或 Git。

## 已知边界

- Bearer Token 是当前本机/内网演示阶段的服务身份机制，不替代生产环境的 mTLS、短期
  令牌、专用 Service Account 或网络策略。
- Nginx 的路径封锁是入口层防护；部署时仍必须让 Gateway 仅加入内部网络，不能直接暴露
  其容器端口。
- CSRF 防护覆盖浏览器 Session 写请求，但不能替代 XSS 防护、输入校验、权限校验或内容
  安全策略。
- `SameSite=Lax` 适用于当前同站部署。如果未来前后端跨站部署，需要重新设计 Cookie、
  CORS 与 CSRF 契约，不能直接放宽为不受控跨域。
