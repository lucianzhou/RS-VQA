# RS-VQA v0.7.0 技术方案与功能介绍：RS-Bot 智能规划

> 状态：后端已完成（UI 改造在 v0.8.0）
> 日期：2026-07-26
> 分支：`feature/rs-bot-agent`，依赖 `feature/gemini-relay-provider`
> 论文：跨模态特征融合机制及微调策略研究与应用
> ADR：[`adr-006-rs-bot-agent.md`](../architecture/adr-006-rs-bot-agent.md)

## 1. 版本目标

把“可信 Agent”从关键词单工具编排升级为真正的 LLM 规划循环，同时让预算、白名单、
拒答、留痕和降级模式全部可强制、可审计。

本版不做：不引入 LangChain4j、不给 Agent 任何写权限、不让 Agent 改写研究模型答案、
不在未配置规划模型时假装智能规划可用。

## 2. 之前的问题

`TrustedAgentService.chooseTool` 用中文关键词从约 20 个工具里挑一个，
`explain` 再用写死的句子解释。于是：

- “汇总项目结果、找出低置信度案例并生成报告草稿”只会命中一个工具；
- 解释文本与工具返回的数字无关；
- 前端显示 `UNCONFIGURED_RULE_BASED_TOOL_ORCHESTRATION`。

## 3. 新增模块

| 文件 | 职责 |
| --- | --- |
| `RsBotPlanner` | 工具调用循环：预算、白名单、拒绝、留痕、取消 |
| `RsBotToolPolicy` | 按会话上下文计算工具白名单 |
| `RsBotPrompt` | 版本化系统提示词与工具输出围栏 |
| `RsBotProperties` | 步数、单步工具数、token、超时、输出截断预算 |
| `AgentSessionTitle` | 本地确定性会话标题生成 |
| `V11__rs_bot_run_provenance.sql` | `agent_run` 增加 provider_state / prompt_version / stop_reason / tool_steps |

## 4. 首版多步示例

用户：**“汇总这个项目的 VQA 结果，找出低置信度案例，并生成报告草稿。”**

RS-Bot 实际执行（由 `callsToolsInSequenceAndSynthesizesFromTheirOutput` 固定）：

1. `project_summary` → 项目规模与调用数
2. `confidence_distribution` → 置信度分箱与低置信度数量
3. `report_draft_data` → 结构化事实包
4. 基于以上工具事实生成中文总结，并说明数字来自哪个工具
5. **不擅自保存报告**；写操作走 proposal，由用户在界面确认后执行

## 5. 预算与限制

| 配置 | 默认 | 作用 |
| --- | ---: | --- |
| `RSVQA_RS_BOT_MAX_TOOL_STEPS` | 6 | 最大规划轮数 |
| `RSVQA_RS_BOT_MAX_TOOL_CALLS_PER_STEP` | 4 | 单步最多执行的工具数 |
| `RSVQA_RS_BOT_MAX_TOTAL_TOKENS` | 40000 | 累计 token 上限 |
| `RSVQA_RS_BOT_TIMEOUT_SECONDS` | 120 | 墙钟超时 |
| `RSVQA_RS_BOT_MAX_TOOL_OUTPUT_CHARS` | 24000 | 单个工具输出截断长度 |

任一预算触发时循环停止，`stop_reason` 记录原因（`max_steps_reached`、`timeout`、
`token_budget_exhausted`、`cancelled`），并给出可读的中文说明而不是空回答。

SSE 断开时 `AgentStreamService` 把 `closed` 标志传入循环，下一步开始前即停止，
不再继续消耗工具调用与 token。

## 6. 安全边界

| 要求 | 实现 |
| --- | --- |
| 工具输出是事实源 | 提示词禁止模型自行计算/补全统计 |
| 会话动态白名单 | `RsBotToolPolicy` 按 project/conversation/batch 绑定计算 |
| 非白名单工具 | 执行前查表拒绝，拒绝结果作为 tool result 回传，并写入 `ToolInvocation` |
| 写操作只生成 proposal | 白名单中没有任何写工具；测试断言与 `ALLOWED_ACTIONS` 无交集 |
| 研究模型答案不可改写 | 提示词明确禁止；结构上 RS-Bot 输出写入 `agent_run`，与 `model_invocation` 分离 |
| 外部模型不可伪装研究模型 | 提示词明确区分；provenance 字段分别记录 |
| RAG 内容不可信 | 工具输出被围栏包裹并声明为数据；出现注入指令时模型须拒绝并说明 |
| 每轮留痕 | provider、model、prompt 版本、tool calls、trace、token、latency、stop_reason |
| Provider 不可用降级 | `RULE_BASED_TOOLS` + 明确提示“RS-Bot 当前处于规则工具模式，未启用智能规划” |

## 7. 会话标题

标题由上下文标签与首轮问题主题推导，例如：

| 首轮问题 | 生成标题 |
| --- | --- |
| 列出需要人工复核的低置信度案例 | `城市土地利用 · 低置信度分析` |
| 汇总这个批量任务的答案分布 | `城市土地利用 · 批量任务分析` |
| 生成这个项目的报告草稿 | `城市土地利用 · 报告草稿` |
| 查询当前模型版本 | `模型版本查询` |

无法识别主题时回退到问题原文（截断并去掉尾部标点）；仍为空时使用 `RS-Bot 分析`。
生成是本地确定性的，不调用 LLM，因此不会失败，也就同时是稳定 fallback。
只在标题仍是占位符且是首轮时替换，用户手动命名的标题不会被覆盖。

## 8. 接口变化

`AgentResponse` 新增：`providerStateLabel`、`providerModel`、`promptVersion`、
`stopReason`、`toolSteps`、`totalTokens`。
`providerState` 取值改为 `LLM_PLANNING` / `RULE_BASED_TOOLS`。
`AgentHistoryRun` 同步新增 `providerState`、`promptVersion`、`stopReason`、`toolSteps`。

`/api/v1/agent/...` 路径保持不变，避免无意义地破坏兼容。

## 10. 已知限制与下一版门槛

- 规划质量依赖中转站模型；`gemini-3.6-flash` 的文本/工具能力仍待用户 live 验证
  （见 v0.6.0 第 7 节）。未配置时自动走规则模式，不影响可用性。
- 前端仍显示旧的“可信 Agent”命名与固定问题按钮；UI 改造在 v0.8.0。
- 下一版门槛：RS-Bot 抽屉成为真正的上下文聊天面板，独立页面显示工具轨迹、引用
  与待确认操作，并补 Playwright 端到端用例。
