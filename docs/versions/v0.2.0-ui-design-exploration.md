# v0.2.0 UI design exploration (draft)

Status: design exploration only; not frozen and no application code changed.

Date: 2026-07-20

## Purpose

This draft turns the RS-VQA MVP from a single upload-and-answer form into a
conversation workspace for one remote-sensing image. It is intended for
review before any further frontend implementation.

The thesis model boundary remains unchanged: the research-model path is the
RSVQA-HR grouped-answer, closed-set classifier deployed with the
`qdrop15 + predicted-soft` protocol. The interface must not present it as a
general-purpose visual assistant or arbitrary remote-sensing analysis system.

## Agreed interaction model

- One uploaded image starts one VQA conversation. Replacing the image starts a
  new conversation rather than mixing two image contexts in one thread.
- The left rail groups projects and historical conversations.
- The main workspace keeps an "image context ribbon" visible above the
  multi-turn conversation.
- Users may type questions freely, while the product makes the validated model
  scope visible and refuses unsuitable questions instead of fabricating a
  research-model answer.
- A future external VLM, if added, must have a distinct source label and must
  not be visually merged with the RS-VQA research-model output.

## Generated design states

The Stitch exploration contains four desktop states in one consistent visual
system:

1. `RS-VQA Remote Sensing VQA Workspace` — active image context and multi-turn
   VQA conversation.
2. `RS-VQA Image Upload Interface` — first-use upload and example-image state.
3. `RS-VQA Image Analysis Loading State` — image analysis in progress.
4. `RS-VQA Out-of-Scope Response` — a restrained, amber-labelled refusal for
   questions outside the verified research-model scope.

## Visual direction

- Deep graphite navigation rail; light canvas and white surfaces.
- Satellite blue is the primary action color; teal and amber are limited to
  status meaning.
- The design signature is the compact image-context ribbon, which ties every
  answer to a specific image.
- Answer first, provenance and confidence second, detailed limitations on
  demand. This avoids turning the core VQA flow into an audit dashboard.

Its UI screens were not transferred during this session because Stitch exposed
the Figma export choice as unavailable and the Figma Starter plan reached its
MCP call limit. No account upgrade, payment, or workaround was attempted.

## Review checklist before implementation

- Confirm the light-main/dark-sidebar visual direction.
- Confirm one-image-per-conversation semantics.
- Review the wording and visual hierarchy of the out-of-scope response.
- Decide whether the Stitch screens should be manually rebuilt as editable
  layers in Figma after the account limit resets, or whether the Stitch export
  integration should be enabled first.

## Out of scope for this design draft

- GPT/DeepSeek or other external VLM model selection.
- Multi-agent panels, RAG panels, account administration, knowledge-base
  management, reporting center, or deployment dashboards.
- New model training, changes to research code, or claims of open-ended VQA.
