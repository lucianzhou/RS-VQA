# RS-VQA v0.1.0 MVP：技术方案与功能介绍

> 状态：已完成（Mock 演示 MVP；尚未接入研究模型运行时）
>
> 版本：v0.1.0
>
> 日期：2026-07-20
> 论文主线：跨模态特征融合机制及微调策略研究与应用

## 1. 本版目标

让用户完成一条最短、可运行、可演示的主路径：

上传一张图像 -> 在输入框提出问题 -> 系统判断该问题是否属于 RSVQA-HR 已验证范围 -> 调用模型服务 -> 展示答案。

本版不把 Agent、RAG、知识库、报告、账户或复杂审计作为前置功能。它们是调研得到的后续增强方向，而不是为凑“企业功能”而提前实现。

## 2. 用户可见功能

| 功能 | v0.1.0 行为 |
| --- | --- |
| 图像上传 | 接收常见 RGB 图片格式并在浏览器中预览 |
| 自由问题输入 | 用户可输入中文或英文，不强制下拉选择 |
| 示例引导 | 提供存在、数量、面积、比较四类可支持问法示例 |
| 问题适配 | 服务端对可识别问法映射为冻结英文 canonical question |
| 模型回答 | 对支持问题展示闭集答案；对不支持问题透明说明能力边界 |
| 模式提示 | 页面明确展示 mock_demo 或 future_research_release，防止误认输出来源 |

## 3. 模型能力与输入边界

正式研究模型的唯一目标协议是：

- 任务：RSVQA-HR grouped-answer closed-set classifier。
- 输入：图像 + 问题文本。
- 类型来源：predicted_soft，不读取人工 question_type_id。
- 问题类别：presence、count、area、comparison。

v0.1.0 的问答框是自由输入框，不是开放式遥感问答接口。系统仅在能明确识别对象词汇与问题类型时才构造 canonical question，例如：

| 用户输入 | Canonical question |
| --- | --- |
| 图中有没有道路？ | Is there a road? |
| How many buildings are there? | How many buildings are there? |
| 建筑物覆盖面积是多少？ | What is the area covered by buildings? |
| 建筑物比道路多吗？ | Are there more buildings than roads? |

若问题为“这里有没有违建”“有何灾害风险”“帮我生成区域描述”等，系统不得调用闭集 ViLT 并给出貌似可靠的回答。

## 4. 架构

浏览器中的 Vue 3 应用负责上传、问题输入、结果展示。

Spring Boot 网关负责 HTTP 接口、请求大小/类型校验和对模型服务的转发。它不拥有模型权重，也不读取训练脚本。

FastAPI 模型服务负责问题匹配、发布模式识别和预测响应契约。它包含两个后端：

| 后端 | 用途 | 输出来源 |
| --- | --- | --- |
| mock | 本机无模型运行时时验证前后端闭环 | mock_demo，必须显式标识 |
| research | 未来加载经发布契约校验的不可变运行时 | research_vilt_predicted_soft |

请求路径：

浏览器 -> Spring 网关 POST /api/v1/vqa/answers -> FastAPI POST /v1/predict -> 响应回浏览器。

## 5. 接口草案

### 网关接口

POST /api/v1/vqa/answers

multipart/form-data：

- image：上传文件
- question：用户输入的文本

核心响应字段：

| 字段 | 说明 |
| --- | --- |
| status | answered、unsupported 或 model_unavailable |
| answer | 回答；未回答时为空 |
| canonicalQuestion | 实际送入模型的冻结问题 |
| questionType | 识别出的四类问题之一 |
| predictionOrigin | mock_demo 或 research_vilt_predicted_soft |
| capabilityNotice | 用户可读边界说明 |

## 6. 真实模型接入门槛

v0.1.0 不下载 checkpoint、不读 data/raw、不启动 GPU。未来接入 research 后端时，必须先验证：

1. model-release.json 存在且满足 rs-vqa-fusion 发布契约。
2. task.name 为 rsvqa_hr_grouped_answer_closed_set。
3. type_source_mode 严格为 predicted_soft。
4. checkpoint、答案词表和运行时 digest 与 manifest 一致。
5. 模型服务不接收 question_type_id、gold answer 或任何评估 metadata。

在这些条件不满足时，服务必须返回 model_unavailable，不能自动回退为未知 checkpoint 或 mock。

## 7. 测试与验收

| 验收项 | 通过标准 |
| --- | --- |
| 支持问法识别 | 中文/英文存在、数量、面积、比较问法映射正确 |

## 10. 已知限制与下一版门槛

- `mock_demo` 的答案是基于输入摘要确定性生成的测试夹具，不能用于任何模型效果判断。
- 本版的问法识别是受控规则匹配；它服务于能力边界，而不是中文自然语言理解研究。
- 尚未接入真实 ViLT、GPU worker、持久化、账户、Agent、RAG、外部 VLM 或 Docker 编排。
- 只有研究仓库产出并通过 `24_model_release_contract.md` 校验的不可变发布物，才可开始 v0.2 的真实 predicted-soft 接入；缺失发布物时必须继续返回 `model_unavailable`，不得静默切换到 Mock 或 oracle/routed 协议。
