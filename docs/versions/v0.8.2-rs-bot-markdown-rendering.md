# RS-VQA v0.8.2: RS-Bot Markdown Rendering

## 版本目标

修复 RS-Bot 将 Gemini 生成的 Markdown 标记作为普通文本直接展示的问题。该变更只作用于 RS-Bot 的综合回答，不改变自研 RSVQA 模型的纯文本预测结果及其来源标识。

## 功能变更

- RS-Bot 回答支持标题、段落、列表、强调、链接、行内代码、代码块、分隔线和 GFM 表格。
- 标题尺寸、段落间距、代码和表格样式适配 Mineral Forest 聊天界面。
- 长 checkpoint 哈希、模型发布 ID 和代码内容可换行或在局部滚动，不撑宽页面。
- 工作区 RS-Bot 抽屉与独立 RS-Bot 页面复用同一个安全渲染组件。
- 模型选择器直接展示 `Gemini-3.6-flash` 与 `Qwen3-VL 32B`，不再使用含糊的“外部通用视觉模型”名称。

## 安全边界

- 不使用 `dangerouslySetInnerHTML`。
- 原始 HTML 不渲染、不执行。
- 链接仅允许 `http`、`https`、`mailto`、站内相对地址和页面锚点。
- `javascript:` 等不安全协议降级为不可点击文字。
- Markdown 图片语法不渲染，避免外部跟踪资源被自动加载。

## 验证

- 组件测试覆盖语义化 Markdown、原始标记消除、HTML 禁用和危险链接拦截。
- 前端完整单元测试：35 项通过。
- TypeScript 类型检查通过。
- Vite 生产构建通过。
- RS-Bot Playwright 布局回归测试：4 项通过。
- 实际页面确认历史 Markdown 回答已渲染为语义化标题、列表、强调和代码。
- 390px 窄屏下页面与回答块均无横向溢出。
- Gemini 中转站真实图像输入探测通过：`gemini-3.6-flash` 接受图像请求，单次探测耗时约 3.7 秒。
- 运行环境恢复为真实发布版 `rsvqa-hr-qdrop15-predicted-soft-20260724-8510bc9`，并确认 `mode=real`。

## Compose 运行注意事项

真实研究模型必须始终同时使用 `compose.yaml` 与 `compose.real.yaml`。仅使用基础 Compose 文件会按设计回落到 Mock。重建演示环境时还需显式保留已配置的 Gemini、Qwen 开关与模型名；密钥继续由仓库外的受限配置文件注入，禁止写入命令、日志或仓库。

## 已知依赖审计项

`npm audit` 报告的两个高危条目均指向仓库已有的 `react-router-dom@7.12.x` 依赖链，与本次新增的 Markdown 渲染依赖无关。本版本不执行可能引入不兼容变化的自动降级修复，后续应单独评估 React Router 官方修复版本。
