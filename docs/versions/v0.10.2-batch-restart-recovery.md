# v0.10.2 批任务重启恢复

状态：已实现并通过真实 PostgreSQL 并发测试与 Gateway 强制终止/重启演练

日期：2026-07-30

## 目标

修复批量 VQA 依赖单进程内存循环的问题，使 Gateway 在处理中断后能够从 PostgreSQL
恢复任务，并阻止双 worker 重复领取、旧执行覆盖新结果或并发计数丢失。本阶段不引入
Kafka、RabbitMQ 或新的基础设施。

## 数据库租约

Flyway `V14__batch_item_leases.sql` 将批任务尝试次数字段规范为 `attempt`，并新增：

- `lease_owner`：本次领取任务项的 Gateway worker 唯一身份；
- `lease_expires_at`：租约到期时间；
- `attempt`：每次成功领取时由数据库原子递增。

数据库约束保证：

- `RUNNING` 项必须同时存在 owner 和到期时间；
- 非 `RUNNING` 项不能残留租约；
- 升级前无法证明 owner 的旧 `RUNNING` 项一次性回到 `QUEUED`。

领取索引按 `batch_job_id + status + created_at + id` 排序，过期租约使用部分索引扫描。

## 原子领取

worker 不再执行“查询队列列表后修改第一项”。新协议在 PostgreSQL 单条事务中使用：

```text
SELECT ... FOR UPDATE SKIP LOCKED
UPDATE ... SET RUNNING, owner, expires_at, attempt = attempt + 1
RETURNING id, attempt
```

因此并行 worker 会领取不同任务项。任务被取消或归档时，不会再产生新租约。

## 幂等完成

模型返回结果落库前必须同时匹配：

- `job_id`；
- `item_id`；
- `status=RUNNING`；
- 当前 `lease_owner`；
- 当前 `attempt`。

匹配时使用悲观行锁。租约过期后，即使旧 worker 随后返回，其 owner/attempt 已失效，结果
会被丢弃，不能覆盖新 worker 的有效完成结果。

成功或失败状态写入后，任务的 `completed_items`、`failed_items` 和最终状态从明细表重新
聚合，不再使用可能在并发下丢更新的 Java 读改写计数。

## 恢复与状态语义

- Gateway 在 `ApplicationReadyEvent` 后立即扫描过期租约和可运行任务。
- 默认每 30 秒再次扫描，以处理启动时尚未到期但原 worker 已终止的租约。
- 默认租约为 10 分钟，长于当前模型请求上限；演练可使用最短 5 秒配置。
- 普通过期项回到 `QUEUED` 并保留历史 attempt。
- 已请求取消的过期项转为 `CANCELLED`，剩余 `QUEUED` 项也同步取消。
- 有活动租约时任务保持 `RUNNING`；无剩余工作后收敛到 `COMPLETED`、
  `COMPLETED_WITH_ERRORS` 或 `CANCELLED`。
- 已归档任务不能重试；运行中的任务不能重试失败项，也不能归档。

相关配置：

```text
RSVQA_BATCH_RECOVERY_ENABLED=true
RSVQA_BATCH_LEASE_DURATION=PT10M
RSVQA_BATCH_RECOVERY_INTERVAL=PT30S
```

## 验证记录

真实 PostgreSQL 17.5：

- Flyway 从 V13 正常迁移到 V14；
- 两个线程同时领取同一任务的两个明细，得到两个不同 ID；
- 第三个 worker 无法重复领取；
- 过期租约重领后 `attempt` 从 1 增加到 2；
- attempt 1 的旧完成请求被拒绝；
- attempt 2 的结果唯一落库，任务计数为完成 1、失败 0；
- 取消后未领取项变为 `CANCELLED`，活动项过期后任务收敛为 `CANCELLED`。

真实 Gateway 强制终止/重启：

- 使用独立 5 秒延迟 Mock 模型服务和临时任务；
- 第一次 Gateway 领取后数据库状态为 `RUNNING:1` 且租约存在；
- 使用 `kill -9` 模拟处理中进程终止；
- 第二次 Gateway 启动后等待旧租约到期并自动恢复；
- 最终状态为 `COMPLETED:2:COMPLETED:1:0`；
- 明细租约已清空，没有永久 `RUNNING`，没有重复有效结果；
- 临时用户、任务、图像、进程和容器均在演练后清理。

固定复验命令：

```bash
scripts/verify_batch_restart_recovery.sh
```

## 已知边界

- 当前租约没有在一次模型调用内部发送心跳，默认时长必须持续高于模型服务的最大请求时长；
  若未来单次推理允许超过 10 分钟，应同时引入续租机制，而不是只增大超时。
- PostgreSQL 是任务事实源，Redis 进度仅为缓存；删除 Redis 数据不会改变任务正确性。
- 单机线程池仍限制本机吞吐量，本阶段目标是可恢复和不重复，不是分布式任务平台。
- worker 在租约失效后仍可能完成已经发出的模型请求，但结果会被幂等门禁拒绝；这会产生
  少量不可避免的重复计算成本，不会产生重复有效结果。
