# RS-VQA 版本文档规范

本目录是 RS-VQA 每个可交付版本的可追溯说明，不以聊天记录代替版本事实。

每次开始一个新版本时，必须新增一个 Markdown 文件，建议命名为：

`v<主版本>.<次版本>.<修订版本>-<简短主题>.md`

每份版本文档至少应包含：

1. 版本号、日期、状态与论文主线关联。
2. 本版目标、用户可见功能和明确不做的内容。
3. 技术方案：模块边界、数据流、接口或配置变化。
4. 模型来源、能力边界和任何 Mock / 外部模型 / 研究模型的隔离方式。
5. 测试、验收结果、已知限制和下一版进入门槛。

版本完成时，将状态改为“已完成”，写入实际验证结果；不要把计划中的能力写成已经交付的能力。

当前版本：[`v0.8.1-integration-review.md`](v0.8.1-integration-review.md)。
