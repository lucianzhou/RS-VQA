# v0.10.0 RAG 租户隔离

状态：已实现，真实 Milvus 验证结果见本文件验收记录

日期：2026-07-30

## 目标

修复多个账户共享同一 Milvus collection 时，私有知识仅按 `index_version` 检索造成的
跨用户片段返回风险。本阶段不改变 BGE 模型、切分算法、RS-Bot 行为或论文研究模型。

## 安全契约

浏览器公开请求不包含 owner。Gateway 从已认证 Spring Security 主体查询当前用户，并向
内部 Knowledge Service 注入：

- `owner_id`：当前用户 UUID；
- `scope`：`PRIVATE` 或 `PUBLIC`；
- `index_version`：固定的知识索引契约版本。

Knowledge Service 不再接受任意 `metadata`，Pydantic 对未知字段使用 `extra=forbid`。
Milvus v2 schema 关闭 dynamic field，并显式保存 `owner_id` 与 `scope`。

私有与公共检索过滤器为：

```text
index_version == current
and (
  (scope == "PRIVATE" and owner_id == authenticated_user)
  or scope == "PUBLIC"
)
```

删除私有知识必须同时匹配 `document_id + owner_id + scope + index_version`。公共知识不能
通过普通删除接口移除。

## 公共知识语义

`RS-VQA 已核准模型边界.md` 是系统管理的全局只读知识：

- 使用固定运行时 ID `builtin:approved-model-boundaries`；
- 数据库按 `scope=PUBLIC + sha256 + index_version` 保证单一版本；
- 首次 seed 的已认证用户只作为创建审计 owner，不限制其他用户读取；
- 普通用户可以检索公共知识，但不能通过文档删除接口删除；
- 重复 seed 返回同一 READY 文档，不重复插入 Milvus。

用户上传的 Markdown/TXT 始终是 `PRIVATE`，不能由客户端升级为公共知识。

## 版本化迁移

- 旧 Milvus collection `rsvqa_knowledge_v1` 保留且不修改 schema。
- 新默认 collection 为 `rsvqa_knowledge_v2`。
- 新默认 index version 为 `rsvqa-knowledge-v2`。
- Flyway `V13__knowledge_tenant_scope.sql` 为关系库增加 `scope`、约束和可见性索引。
- 旧数据库记录迁移为 `PRIVATE`，不会自动复制到 v2；需要由所有者重新上传。
- 内置边界文档需要在 v2 首次执行一次受控 seed。

这一策略避免在原集合上静默改变 schema，也避免旧向量在没有显式 owner/scope 时进入新检索。

## 接口变化

内部 Knowledge Service：

- `POST /v1/documents` 必须携带 `owner_id`、`scope` 和 `index_version`；
- `POST /v1/search` 必须携带 `owner_id`、`index_version`，可显式控制
  `include_public`；
- `DELETE /v1/documents/{id}` 必须携带 tenant/scope/version 查询参数；
- 直接运行检索评测脚本时必须传入 `--owner-id`。

这些接口只在 Compose backend 网络中使用，不是浏览器公开 API。

## 测试与验收

自动测试：

- Knowledge Service：9 passed；
- Gateway：94 passed，2 skipped；
- Java 合约覆盖认证 owner 注入、私有上传、公共 seed 和 tenant-bound delete；
- Python 覆盖任意 metadata 拒绝、缺 tenant 请求拒绝、公共删除拒绝和过滤器生成；
- A/B 双用户分别索引唯一私有文档，双方可见集合分别严格为 `{doc-a}` 与 `{doc-b}`。

真实 Milvus v2 验证：

- 使用独立 v0.4.0 Knowledge Service 临时容器连接现有 Milvus；
- 用户 A 可见 `p0-a-private + p0-public-boundary`；
- 用户 B 可见 `p0-b-private + p0-public-boundary`；
- 双向私有跨租户命中为 0；
- 使用用户 B owner 删除 A 文档后，A 文档仍可检索；
- 正确 owner 删除私有文档成功；
- 普通接口删除 PUBLIC 文档返回 HTTP 403；
- 验证后已删除全部临时文档、临时容器和临时镜像。

真实 PostgreSQL 17.5 迁移验证：

- 在全新临时数据库上启动打包后的 Gateway；
- Flyway 成功验证并依次应用 V1–V13，最终记录为 `13:true`；
- `knowledge_document.scope`、`idx_knowledge_document_visibility` 和
  `uq_knowledge_public_release` 均实际存在；
- 验证完成后已停止 Gateway 并删除临时数据库容器。

阶段验收要求：

- A 检索 B 私有知识：0；
- B 检索 A 私有知识：0；
- 客户端不能通过 Gateway 指定 owner；
- 公共知识双方可读取，普通删除接口不可删除；
- v1 collection 保持不变。

## 已知边界

- Knowledge Service 信任来自 backend 网络的 Gateway 身份注入；MCP、网络与应用认证在
  v0.10.1 阶段收紧。
- 本阶段不实现组织级 tenant、管理员公共知识管理界面或跨组织共享。
- 旧 v1 私有文档不会自动迁移，避免无 owner/scope 的旧向量被错误授权。
