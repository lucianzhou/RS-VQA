# RS-VQA v0.8.0 技术方案与功能介绍：RS-Bot 界面改造

> 状态：已完成
> 日期：2026-07-26
> 分支：`feature/rs-bot-ui`，依赖 `feature/rs-bot-agent` → `feature/gemini-relay-provider`
> 论文：跨模态特征融合机制及微调策略研究与应用

## 1. 版本目标

把后端已经具备的多步工具编排暴露成可用的界面：统一命名为 RS-Bot，把工作区抽屉从
“几个固定问题按钮”改成真正的上下文聊天面板，并让抽屉与独立页面共享同一套状态与接口。

## 2. 用户可见变化

| 位置 | 变化 |
| --- | --- |
| 侧栏导航 | “可信 Agent” → “RS-Bot” |
| 工作区顶栏按钮 | “可信 Agent” → “RS-Bot” |
| 独立页面标题 | “RS-Bot / 可信遥感分析助手” |
| 工作区抽屉 | 完整消息历史、工具执行状态、固定底部输入框、可取消 |
| 独立页面 | 保留左侧会话列表；中间改用同一个聊天组件，含工具轨迹与 trace |
| 待确认操作 | 默认收起；有待确认项时自动展开，并在标题栏显示数量徽标 |
| 会话标题 | 由上下文与首轮问题生成，不再出现 `Agent action 178491…` |
| 运行状态 | 显示“RS-Bot 当前处于规则工具模式，未启用智能规划”，不再显示状态令牌 |

## 3. 抽屉与独立页面共享一套状态

要求“抽屉与独立页面功能要共享状态/API，不能形成两个互不一致的 Agent”，因此新增：

| 文件 | 职责 |
| --- | --- |
| `src/rsbot.ts` | `useRsBotSession`：会话查询、流式运行、阶段、取消、失效刷新；名称与文案常量 |
| `src/components/RsBotChat.tsx` | 唯一的对话渲染组件：转录、工具轨迹、建议、固定底部输入框 |

两个界面都调用同一个 hook 与同一个组件，差异只有 `compact` 布局变体。工作区抽屉此前有
自己的一份 mutation、自己的 stage 与自己的结果渲染，现在已删除。

## 4. 布局与样式修复

### 4.1 `新建分析会话` 按钮

`.primary-button` 只有 `min-height/padding/background`，没有 `display: inline-flex`，
因此前置图标是一段内联内容：与文字之间没有 gap，并且在
`.agent-context-builder .primary-button { width: 100% }` 之类规则把按钮拉满宽度后会贴到边缘。
`.agent-context-builder .primary-button` 曾试图用 `justify-content: center` 修补，
但在非 flex 容器上该属性无效。

修复：`.primary-button` 本身改为 `inline-flex + align-items:center + justify-content:center + gap:6px`，
并删除 `.report-create-bar` / `.report-document-heading` / `.signed-out` 里重复的补丁。

Playwright 断言的是几何而不是文案：computed `display/justify-content/align-items/column-gap`，
图标左边缘距按钮左边缘 > 8px，且图标整体位于按钮中线左侧。

### 4.2 标题截断与按钮排布

`.agent-context-header` 的 `h1`/`p` 增加 `overflow/text-overflow/white-space`，
`.agent-context-identity` 加 `min-width: 0`，受控操作按钮 `flex: 0 0 auto`。
生成的长会话标题会省略号截断，而不是把右侧控件挤出表头。

### 4.3 滚动容器

`.agent-conversation` 由固定 `grid-template-rows` 改为 flex 列：待确认操作面板是条件渲染的，
固定行会在它缺席时把 `1fr` 分配给错误的子元素。唯一滚动容器是 `.rsbot-transcript`
（`overflow-y: auto` + `overscroll-behavior: contain`），页面本身不产生横向滚动。

### 4.4 动效与 reduced motion

沿用现有 `motion/react` 与 lucide 图标，没有引入新依赖，没有全屏绿色背景，保持
Mineral Forest 配色与既有留白节奏。`prefers-reduced-motion: reduce` 时
`.rsbot-progress-line::after` 动画关闭并改为静态填充，转录容器 `scroll-behavior: auto`。

| 套件 | 结果 |
| --- | --- |
| `npm run typecheck` | 通过（另用 `--noUnusedLocals --noUnusedParameters` 清理了残留代码） |
| `npm test` | **29 passed**（新增 `RsBotChat.test.tsx` 8 例） |
| `npm run build` | 通过 |
| Playwright desktop | **12 passed / 1 failed**（见第 6 节） |
| Playwright mobile | 1 passed |
| Playwright tablet | 1 passed |
| `apps/gateway` `mvn test` | 76 passed（继承自 v0.7.0，本版未改后端） |

新增 Playwright 用例 `e2e/rsbot.spec.ts`：按钮图标居中几何、页面无横向滚动、
转录独立滚动、抽屉聊天面板与固定底部输入框、reduced motion 动画关闭。

`RsBotChat.test.tsx` 覆盖：单轮渲染与 provenance、多工具轨迹含被拒绝调用、
规则模式提示文案、提前停止原因、发送并清空输入、运行中取消、建议仅在首轮出现、
错误可被辅助技术读取。

### 两个在验证过程中发现并修复的问题

1. **e2e 竞态**：工作区多轮 VQA 用例在第二个答案落库前就 `page.reload()`，
   在真实模型的延迟下会读到只写了一半的会话。改为先等待“正在分析当前影像…”消失。
2. **reduced motion 用例假通过**：`test.describe` 里的 `test.use({ reducedMotion })`
   在本项目的 project 配置下未生效（实测 `matchMedia(...).matches === false`），
   断言会因为媒体查询根本没匹配而“通过”。改为显式 `page.emulateMedia` 并先断言媒体查询已生效。
   CSS 本身经核对是正确的（已从容器实际下发的 bundle 中确认）。

## 6. 已知失败与环境说明

`e2e/workspace.spec.ts` 的 “indexes approved knowledge and returns citations from BGE and Milvus”
**失败**，原因是本机没有启动 `knowledge-service` 与 `milvus` 容器（两者在 `compose.yaml` 中已定义，
但当前环境只运行 postgres / redis / model-service / gateway / web）。这与本版改动无关；
启动完整 Compose 后应重跑该用例。

## 7. 跨分支迁移冲突（需要在合并时处理）

`fix/research-model-canonical-question` 增加了 `V10__question_normalization_audit.sql`，
`feature/rs-bot-agent` 增加了 `V11__rs_bot_run_provenance.sql`。两者在各自分支上独立编号。

本机开发数据库当前只应用了 `V11`（因为运行的是本分支）。合并时：

1. 先合并 `fix/research-model-canonical-question`（V10），再合并 RS-Bot 分支（V11）；
   全新数据库按序应用，没有问题。
2. 已经应用过 V11 的既有开发库，需要 `spring.flyway.out-of-order=true` 或
   `flyway repair` 之后再启动，否则 Flyway 会拒绝乱序的 V10。

这是分支并行开发的必然结果，不是缺陷，但必须在合并前显式处理。

## 8. 边界（未变）

- RS-Bot 没有写权限；创建任务、保存报告、导出、归档仍走 proposal → 人工确认。
- 研究模型原始答案不被 RS-Bot 改写；外部模型输出不与研究模型混同。
- 研究模型指标不变：test OA/AA = 0.8401412 / 0.8390032，
  test_phili OA/AA = 0.8031558 / 0.7975786；不声称 SOTA。
